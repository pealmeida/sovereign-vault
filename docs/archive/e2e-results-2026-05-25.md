## 4. Findings / bugs — and fixes

1. **OTP unusable over MCP → FIXED (`4d50699`).** The OTP modal originally only displayed a code with no input, and the tool schemas had no `otp` param, so OTP ops could never complete (deny/timeout only). Redesigned as a **cross-channel challenge/response**: gated tools accept an optional `otp` arg; the first call issues a single-use, 120s-TTL code shown in a **display-only** desktop modal and returns `otp_required` immediately; the agent resends with `otp=<code>`; the vault validates per request-signature, consumes it, and auto-closes the modal. Code is shown in one channel (desktop) and entered in another (agent), binding the session. **Verified live:** create + write on an OTP container complete via resend; replayed code rejected (single-use). ✅
2. **Approval-request retry storm → FIXED (`be4e838`).** A timed-out/disconnected MCP client left a long-lived pending approval and reconnect+retry stacked modals faster than dismissable. `ApprovalState` now dedupes by request signature — a duplicate supersedes the stale one and emits `vault://approval-cancel`; timeout cut 300s→120s also cancels. OTP no longer blocks at all (returns immediately). **Verified live:** two identical encrypts collapsed to a single modal; superseded call returned at once. ✅
3. **ANONYMIZED / ZKP / NATIVE** advertised in the mode enum but not implemented for live MCP (`"...not implemented for live MCP access"`). Still open — should be hidden from the create surface or marked experimental until implemented.
4. **No single-instance guard → FIXED (`be4e838`).** Added `tauri-plugin-single-instance` (registered first); a second launch focuses the existing window. (Note: the "two SV processes" earlier were one app's main + WebView2 worker, not two instances.)
